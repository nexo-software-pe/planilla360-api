# CLAUDE.md — planilla360-api

Backend de **Planilla360** (Nexo Software S.A.C.): SaaS multi-empresa de RRHH y planillas para pymes peruanas.

## Stack
Java 21 (fijado con maven-enforcer) · Spring Boot 4.1.x · Spring Modulith · Spring Security (resource server JWT) · Spring Data JPA + Hibernate 7 · Flyway · PostgreSQL · Redis (caché) · RabbitMQ (Spring AMQP) · MinIO/R2 (AWS SDK S3) · OpenPDF · Apache POI · JavaMail (Mailpit) · Resilience4j · MapStruct · springdoc · Bucket4j · ShedLock · Maven Wrapper.
Pruebas: JUnit 5, AssertJ, Mockito, spring-security-test, Testcontainers (PostgreSQL, Redis, RabbitMQ, MinIO, Mailpit), WireMock, Awaitility, ArchUnit, Spring Modulith.
(La observabilidad completa se incorpora en una fase posterior.)

## Comandos
Usar JDK 21 (`JAVA_HOME` o SDK del proyecto en IntelliJ). Los tests de integración necesitan Docker Desktop encendido.
```
docker compose --profile full up -d   # PostgreSQL, Redis, RabbitMQ, MinIO, Mailpit y WireMock (core = solo PostgreSQL)
./mvnw spring-boot:run                # perfil local, puerto 8080, datos ficticios de desarrollo
./mvnw verify                         # compila, tests, Checkstyle, Spotless, JaCoCo (≥ 80 %) y PIT (dominio)
./mvnw test -Dtest='ValidadorCierreTests*'   # solo unas pruebas (las clases @Nested llevan * al final)
```
JaCoCo (≥ 80 %) y PIT (≥ 85 %) cubren los dominios de planilla, asistencia y vacaciones. Informes: `target/site/jacoco/index.html` (cobertura) y `target/pit-reports/index.html` (mutación). Escenarios Cucumber: `EscenariosPlanillaTests`.
Desde PowerShell: `.\mvnw.cmd verify`. Si falla, usar la terminal de Git Bash.
Swagger (solo local/staging): http://localhost:8080/swagger-ui.html — botón *Authorize* con el `accessToken` del login.

## Convenciones
- **Dominio en español** (clases, métodos de negocio, eventos, tablas, API). **Infraestructura en inglés** (config, filtros, adapters técnicos, sufijos `Controller`/`Service`/`Repository`).
- Paquete base `pe.nexosoftware.planilla360`; un paquete raíz por módulo (Spring Modulith). Un módulo solo usa la **API pública** de otro (las clases de su paquete raíz) o sus **eventos**; el interior (`controller/service/repository/entity/dto/mapper`) es privado.
- Núcleo (planilla, asistencia, vacaciones): hexagonal `domain/ application/ infrastructure/`. Soporte: capas clásicas. `ArquitecturaTests` (ArchUnit) hace cumplir las reglas.
- Controllers: reciben/devuelven **DTO** (records), nunca entidades; validación con Bean Validation; autorización con `@PreAuthorize` (roles `ADMIN_SAAS`, `ADMIN_EMPRESA`, `RRHH`, `EMPLEADO`). Listados paginados con `Pagina<T>` y `?page=&size=&sort=`.
- Errores: se lanzan excepciones de `compartido.excepcion` (`RecursoNoEncontrado`, `Conflicto`, `ReglaDeNegocio`…); `GlobalExceptionHandler` las convierte a `application/problem+json`.
- **Multi-tenant por columna `tenant_id`**: el tenant sale del JWT (`TenantContextFilter` → `TenantContext`). Las entidades de negocio llevan `@TenantId` de Hibernate (filtra lecturas y asigna el tenant al guardar). `Usuario` y `AuditoriaCambio` no (el tenant puede ser nulo): sus servicios filtran explícitamente. Un recurso de otra empresa se responde **404**. Las consultas SQL nativas NO se filtran solas: incluir `tenant_id` a mano.
- Auditoría: `created_at/by`, `updated_at/by` con `AuditableEntity`; para el historial, publicar `CambioRegistrado` (lo guarda el módulo `auditoria` en la misma transacción). Nunca incluir contraseñas en las instantáneas.
- Parámetros legales (RMV, UIT, tasas) se leen de `CatalogoApi.valorParametro(codigo, fecha)`; nunca se escriben en el código.
- **TDD en el dominio**: primero el test en rojo (commit `test:` con un esqueleto que compila y lanza `UnsupportedOperationException`), luego la implementación (`feat:`) y, si hace falta, el `refactor:`. Los tests del dominio van en paquetes `..domain..` / `compartido.dominio` porque PIT solo ejecuta esos. Un cambio en el dominio no se da por bueno si baja el PIT por debajo de 85 % o la cobertura por debajo de 80 %.
- **Dominio de asistencia/vacaciones**: sus excepciones extienden `compartido.dominio.ReglaDeDominioException` (el `GlobalExceptionHandler` las responde 422). Los casos de uso de `application/` dependen de puertos; otros módulos se consultan solo por un adaptador en `infrastructure/adapter`. `ArquitecturaHexagonalTests` lo hace cumplir. Los eventos entre módulos se publican con Spring (síncronos, misma transacción); las clases de evento viven en la raíz del módulo emisor.
- Dinero siempre con `Dinero` (nunca `double`). Fechas: `LocalDate`/`Periodo`; el dominio no llama a `LocalDate.now()` (la fecha se recibe como dato).
- Commits: Conventional Commits. Ramas: `feat/<n>-...`, `fix/<n>-...`, PR a `staging`.
- **Ningún secreto en el repo**: variables de entorno; `.env.example` documenta las variables. En local la API genera un `JWT_SECRET` efímero si no se define.

## Dónde vive qué
- `compartido/` (módulo abierto): `tenant/TenantContext`, `seguridad/` (Rol, UsuarioAutenticado), `excepcion/`, `dominio/` (Ruc, Dni), `validacion/`, `persistencia/AuditableEntity`, `paginacion/Pagina`, `eventos/CambioRegistrado`.
- `compartido/infrastructure/` — `SecurityConfig` (cadena de filtros), `JwtConfig`, `GlobalExceptionHandler`, `HibernateTenantConfig`, `CorsConfig`, `OpenApiConfig`, `JpaAuditingConfig`, `CacheConfig`.
- `empresa/` — empresas cliente (`/api/v1/empresas`, solo ADMIN_SAAS). API pública: `EmpresaApi`.
- `identidad/` — login, refresh con rotación, logout, perfil, cambio de contraseña (`/api/v1/auth`) y usuarios (`/api/v1/usuarios`). Rate limit de login con Bucket4j.
- `catalogo/` — áreas y cargos (por empresa), AFP, parámetros legales versionados y feriados (globales, con caché). API pública: `CatalogoApi`.
- `auditoria/` — historial de cambios (`/api/v1/auditoria`).
- `empleado/` (capas clásicas) — empleados, contratos y familiares (`/api/v1/empleados`, RRHH/ADMIN_EMPRESA). La búsqueda usa el patrón **Specification** (`service/EmpleadoSpecs`: cada criterio es una pieza que se combina con `and`; filtro `FiltroEmpleados`). API pública: `EmpleadoApi` (`buscar`, `deUsuario`, `vigentesEn`). El DNI no se modifica; el cese fija estado y fecha; el contrato nuevo cierra el anterior; la jerarquía de jefes no admite ciclos.
- `asistencia/` (**hexagonal**) — `domain/` (Java puro: `Horario`, `ConsolidadorAsistencia`, `PoliticaMarcacion`, `HoraExtra`), `application/` (`port/in` casos de uso, `port/out` puertos, `service/`), `infrastructure/` (`persistence/{entity,repository,adapter}`, `web/{controller,dto,mapper}`, `adapter/` hacia empleado y catálogo, `scheduling/ConsolidacionDiariaJob`, `event/` listener de vacaciones). Endpoints: `/api/v1/asistencia` (marcaciones, `mia`, resumen, consolidaciones, `horas-extra`) y `/api/v1/horarios`.
- `vacaciones/` (**hexagonal**) — `domain/` (`PoliticaVacaciones` Strategy sellada, `PeriodoVacacional`, `CalculadoraPeriodos`, `SolicitudVacaciones` + `EstadoSolicitud` State, `Permiso`), mismas capas que asistencia. Publica los eventos `VacacionesAprobadas` y `PermisoAprobado` (raíz del módulo = API pública); asistencia los escucha y justifica los días. Endpoints: `/api/v1/vacaciones` (saldo, solicitudes, aprobar-jefe, aprobar-rrhh, rechazar, cancelar, venta) y `/api/v1/permisos`.
- **Jobs programados**: `SchedulingConfig` (ShedLock sobre la tabla `shedlock`, `LockingTaskExecutor`; `app.jobs.habilitados=false` apaga los `@Scheduled`, p. ej. en tests). El job pide el bloqueo explícitamente (`executeWithLock`) y recorre las empresas con `EmpresaApi.porCadaEmpresaActiva` (fija el tenant y sigue si una falla). Asistencia 00:30, vacaciones 00:10 y pre-cálculo de planilla 23:00 (solo actúa el último día hábil del mes), hora de Lima.
- `compartido/dominio/` — value objects `Dinero` (BigDecimal, 2 decimales, redondeo HALF_UP, `proporcional` redondea una sola vez) y `Periodo` (YearMonth), además de `Dni` y `Ruc`.
- `planilla/` (**hexagonal**; API pública = el evento `PlanillaCerradaEvento` de la raíz). `domain/` es **Java puro**:
  - `model/` — `Planilla` (agregado; `cerrar` es idempotente por clave y devuelve el evento `PlanillaCerrada`), `EstadoPlanilla` (State: BORRADOR → CALCULADA → CERRADA, + ANULADA), `LineaPlanilla` + `Builder` (boleta: totales, neto y `conceptos()`), `ParametrosLegales` (RMV, UIT y tasas llegan como datos, nunca hardcodeados), `Gratificacion`, `DepositoCts`.
  - `regimen/` — `RegimenPensionario` (Strategy sellada: `Onp`, `Afp`) + `FabricaRegimenPensionario` (Factory); `RegimenLaboral` (general / pequeña empresa).
  - `service/` — calculadoras sin estado: asignación familiar, tardanzas e inasistencias, gratificación, CTS y renta de 5.ª categoría (simplificada: impuesto anual ÷ 12).
  - `validation/` — cadena de validaciones de cierre (`ValidadorCierre.estandar()`): reúne **todas** las incidencias, no corta en la primera.
  - `excepcion/ReglaDePlanillaException` — error de negocio del dominio (sin Spring); extiende `ReglaDeDominioException`, así que la API responde 422.
  - Fase 5a: `service/CalculadoraLineaMensual` (Template Method del mes de un trabajador: básico proporcional a los días laborados, asignación familiar, horas extra, descuentos de asistencia, pensión por Strategy y retención de 5.ª), `CalculadoraLineaSemestral` (líneas de gratificación y CTS), `CalculadoraHorasExtra` (25 %/35 %), `CalculadoraTiempoDeServicio` + `model/SemestreDeBeneficio`, `JornadaLaboral` (horas diarias = salida - entrada - refrigerio del horario asignado, con tope de 8 h; sin horario, jornada semanal ÷ días laborables del contrato), `CalendarioLaboral` (último día hábil); `LineaPlanilla` ahora lleva `cts`; `Planilla.reconstruir` rehidrata desde el almacenamiento.
  - `application/` — `port/in` (`GestionarPlanillasUseCase`, `CerrarPlanillaUseCase`, `AnularPlanillaUseCase`, `RegistrarPagoUseCase`, `PrecalcularPlanillaUseCase`), `port/out` (`PlanillaPort`, `HistorialPlanillaPort`, `PagoPlanillaPort`, `ConsultaPersonalPort`, `ConsultaCatalogoPort`, `ConsultaEmpresaPort`, `ConsultaAsistenciaPort`, `ConsultaVacacionesPort`, `PublicadorEventosPort`) y `service/` (`PlanillaService`, `CierrePlanillaService`, `AnulacionPlanillaService`, `PagoPlanillaService`, `PrecalculoService`; `ArmadorDeLineas`, `ValidadorDePlanilla` y `PersonalDelPeriodo` son piezas internas del paquete).
  - `infrastructure/` — `persistence/{entity,repository,adapter}` (tablas `planilla`, `linea_planilla`, `concepto_planilla`, `pago_planilla`; la fila se bloquea con `PESSIMISTIC_WRITE` al calcular, cerrar, anular y pagar), `adapter/` hacia empleado, empresa, catálogo, asistencia y vacaciones (capa anticorrupción), `event/PlanillaEventosAdapter`, `scheduling/PrecalculoPlanillaJob`, `seed/SembradorPlanillasLocal` (solo `local`), `web/{controller,dto,mapper}`.
  - Endpoints (`/api/v1/planillas`, RRHH y ADMIN_EMPRESA): `POST /` (crear borrador), `GET /` (filtros `periodo`, `tipo`, `estado`), `GET /{id}`, `POST /{id}/calcular`, `GET /{id}/lineas`, `GET /{id}/validaciones`, `POST /{id}/cerrar` (cabecera obligatoria `Idempotency-Key`; repetir devuelve la misma planilla con `Idempotent-Replayed: true`), `POST /{id}/anular` (solo ADMIN_EMPRESA, motivo obligatorio, sin pago registrado), `POST /{id}/pago`, `POST /gratificacion` y `POST /cts` (`simular` por defecto; con `simular=false` generan la planilla calculada).
  - Reglas de aplicación: una sola planilla vigente (no anulada) por periodo y tipo; no se trabaja un periodo futuro; la gratificación solo en julio y diciembre, la CTS solo en mayo y noviembre; la planilla mensual NO incluye la gratificación ni la CTS (van en sus propias planillas); las validaciones de asistencia y vacaciones solo condicionan la mensual.
- Pruebas del dominio: `src/test/.../planilla/domain/**` (unitarias, AssertJ, parametrizadas; `ParametrosLegalesBuilder` y `LineasDePrueba` son test data builders) y escenarios Gherkin en español en `src/test/resources/features/planilla/*.feature` con sus pasos en `planilla/bdd/`.
- **Fase 5b — boletas y procesos asíncronos** (los módulos de soporte usan capas + Adapters; cada puerto tiene su adaptador):
  - `boleta/` — `Boleta` (tabla `boleta`, una por trabajador y planilla; estados PENDIENTE → GENERADA → ENVIADA, o FALLIDA). Puertos/adapters: `pdf/GeneradorBoletaPdf` (OpenPDF), `almacenamiento/AlmacenArchivos` (`S3AlmacenArchivos` para MinIO/R2 y `MemoriaAlmacenArchivos`), `mensajeria/ColaBoletas` (`RabbitColaBoletas` o `EnProcesoColaBoletas` según `app.messaging.enabled`). `PlanillaCerradaListener` (tras confirmar el cierre) → `BoletaService.generarMasivo` crea las filas y encola un mensaje por trabajador → `ConsumidorBoletas` → `GeneracionBoletaService.generar` (idempotente, transacción propia) → evento `BoletaGeneradaEvento`. Endpoints: `POST /api/v1/planillas/{id}/boletas/generar` (202), `GET .../boletas/estado`, `GET .../boletas`, `GET /api/v1/boletas/mias`, `GET /api/v1/boletas/{id}/pdf`. API pública: `BoletaApi`, `BoletaGeneradaEvento`.
  - `notificacion/` — `BoletaGeneradaListener` encola el aviso, `ConsumidorCorreos` lo envía con `EnvioCorreoService` (plantilla `templates/correo/boleta.html`) y marca la boleta ENVIADA.
  - `compartido/mensajeria/` — `Colas` y `MensajeriaConfig` (exchange de trabajo + DLX, cada cola con su DLQ, mensajes JSON). Los consumidores reintentan (`spring.rabbitmq.listener.simple.retry`) y al agotarse el mensaje se republica en la DLQ; el consumidor de la DLQ marca la boleta FALLIDA. Cualquier consumidor fija el tenant con `TenantContext` desde el mensaje y lo limpia al terminar.
  - `planilla/PlanillaApi` (datos de las líneas para boletas), `empleado/FichaEmpleado` y `EmpleadoApi.registrar/existeDni`, nuevas consultas por nombre en `CatalogoApi`.
  - `importacion/` — importación de empleados desde Excel (`LectorHojaExcel` con adaptador POI); valida fila por fila, `simular=true` por defecto. `reporte/` — SQL nativo con `JdbcClient` (CTE + `RANK()`, `ROLLUP`, función de ventana) sobre la vista `vista_planilla_detalle`; **siempre filtran `tenant_id`**; exporta el Excel de la planilla. `integracion/` — `ProveedorConsultas` (adaptadores `HttpProveedorConsultas` y `StubProveedorConsultas`) detrás de `ResilienciaExterna` (reintentos + cortacircuito de Resilience4j): 404 = no existe y no se reintenta; 5xx/timeout = transitorio; circuito abierto o reintentos agotados = 503 (`ServicioNoDisponibleException`); tipo de cambio con caché y último valor conocido.
  - Gotcha: un oyente `@TransactionalEventListener(AFTER_COMMIT)` sigue enlazado a la transacción ya terminada; lo que escriba en la base debe usar `REQUIRES_NEW` (por eso `GeneracionBoletaService.generar` y `BoletaService.marcarEnviada`).
  - Seed local: `R__seed_local_personal_asistencia.sql` (6 meses + mes en curso, reglas del consolidador) y `SembradorPlanillasLocal` (cierra el historial con `CerrarPlanillaUseCase`, validaciones incluidas, dentro de `CargaHistorica` para no disparar boletas ni correos). `SeedLocalTests` verifica que el seed pasa las validaciones.
- `src/main/resources/db/migration` — Flyway (`V1` esquema, `V2` datos referenciales, `V3` empleados, `V4` asistencia + `shedlock`, `V5` vacaciones, `V6` planilla, `V7` refrigerio del horario y días laborables del contrato, `V8` boletas y la vista de reportes). `db/seed/local` — datos ficticios (empresas, usuarios y personal/asistencia/vacaciones), solo perfil `local`.
- `src/main/resources/application*.yml` — configuración por perfil (`local`, `staging`, `prod`); `src/test/resources/application-test.yml`.
- `src/test/.../soporte` — `IntegracionBase` (app completa + PostgreSQL real), `TestcontainersConfig`, `PersonalBase` (empresa + área + cargo + RRHH + empleados listos) y `RelojDePrueba` (reloj fijable; las pruebas usan fechas de 2030 para que los JWT sigan siendo válidos).
- `Dockerfile`, `compose.yaml` — imagen multi-etapa (sin root) y servicios locales por perfiles.
- `config/checkstyle/checkstyle.xml` — reglas de estilo. `.github/workflows/ci.yml` — CI.
